# Roadmap

SeqDoc broadens compiler-evidenced traversal while preserving evidence, certainty, deterministic output, profile
isolation, and conservative boundaries.

The canonical staged v1 strategy is [the completion roadmap](project/completion-roadmap.md). Its readable companion is
[the plain-English completion visual](project/completion-roadmap-visual.md). Current lifecycle, dependencies, and
selection come from the [work-item registry](project/work-items/), not this summary.
The detailed future issue plan is [the completion issue map](project/completion-issue-map.md).

CreditTransfer is the primary whole-solution acceptance target. FraudManagement, SMSGateway, TicketReservation, and
unrelated projects protect generality and false-positive boundaries. The roadmap prioritizes useful diagrams first;
release, packaging, and broader infrastructure follow measured capability gaps.

## Direction

1. Complete independent audits and freeze accepted foundations.
2. Deliver service, persistence, worker, control-flow, traversal, and configuration slices independently.
3. Accept each lane, then compose whole-solution views and the supported-framework matrix.
4. Finish wording, rendering, CLI, performance, compatibility, security, and release inputs.
5. Package and release only after the support matrix and reproducible release decision are proven.

Longer-term work—incremental reuse, explanation/search, broader frameworks, and language polish—requires measured need
and a fresh decision ticket.
